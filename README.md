# Task Service

Сервис для управления задачами с HTTP API на Go.

## КЛЮЧЕВЫЕ ИЗМЕНЕНИЯ

### Поддержка периодических задач (RRULE)
- Добавлена возможность создавать задачи-шаблоны с правилами повторения в формате RRULE (RFC 5545).
- Поддерживаются ежедневные, еженедельные, ежемесячные и сложные календарные повторения, а также исключения (`EXDATE`) и дополнительные даты (`RDATE`).

### Автоматическая генерация экземпляров
- Фоновый воркер (`PeriodicWorker`) с интервалом 1 минута вычисляет ближайшую дату выполнения и создаёт экземпляр задачи.
- Гарантируется создание только **одного** экземпляра на каждую дату благодаря уникальному индексу `(parent_id, scheduled_for)`.

### Устранение дублирования и точное соблюдение расписания
- Исправлена проблема, при которой ежедневные задачи создавались каждую минуту. Решение: явная передача `DTSTART` (времени создания шаблона) в библиотеку `rrule-go`.
- Метод `UpdateLastRunAt` точечно обновляет поле `last_run_at` родительской задачи, исключая повторную обработку одной и той же даты.

### Архитектурная декомпозиция
- Логика генерации экземпляров вынесена в отдельные use‑case (`ProcessRecurringTasksUseCase`, `CreateInstanceUseCase`).
- Воркер перемещён в слой `internal/worker` и отвечает только за запуск по таймеру.
- Применены паттерны **Strategy** и **Factory** для поддержки различных типов периодичности без изменения бизнес-логики.

## Требования

- Go `1.23+`
- Docker и Docker Compose

## Быстрый запуск через Docker Compose

```bash
docker compose up --build
```

После запуска сервис будет доступен по адресу `http://localhost:8080`.

Если `postgres` уже запускался ранее со старой схемой, пересоздай volume:

```bash
docker compose down -v
docker compose up --build
```

Причина в том, что SQL-файл из `migrations/0001_create_tasks.up.sql` монтируется в `docker-entrypoint-initdb.d` и применяется только при инициализации пустого data volume.


```text
http://localhost:8080/swagger/openapi.json
```

## API

Базовый префикс API:

```text
/api/v1
```

Основные маршруты:

- `POST /api/v1/tasks`
- `GET /api/v1/tasks`
- `GET /api/v1/tasks/{id}`
- `PUT /api/v1/tasks/{id}`
- `DELETE /api/v1/tasks/{id}`
